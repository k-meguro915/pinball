## 1. 今の台（調べたこと）
- 台は `DBTableBuilder`（Tools > Pinball Dodgeball > Build Dodgeball Table）がコードで作る。寸法は `DBConst`。
- 各ゴールの側にフリッパー 2 本とガイド（斜めの壁）。ガイドの上に加速レーン、ガイドと外壁の角にシュートポスト。
- フリッパーの真ん中から落ちると、その陣地の角の相手のシュートポストに球がセットされ、撃たれる。
- 台は「中央が山」の傾き（`DBBall.slopeAcceleration`）。球は今いる側のゴールへ加速する。フリッパーがそれを打ち返す。
- 選手 3 人は 1 列（`DBBlockerRow`）。動ける範囲は Z 1.0〜6.05。ゴール側の壁は Z 13.5。
- ドロップターゲットを 3 つ倒すと、シュートポストに球がセットされる。
- コースターに乗るのは、自分のフリッパーで打った球だけ（`flipperShotsOnly`）。
- CPU はフリッパーを自動で振るだけで、**キャッチをしない**（よけるだけ）。

## 2. フリッパーをなくすと困ること
| # | 困ること | 案 |
|---|---|---|
| A | 傾きで球が自陣の奥へ行き、壁ぎわで止まる。選手の範囲（Z 6.05 まで）からは届かない | 内野をエンドラインの壁まで広げる。傾きを弱くする。自陣でゆっくりになった球は、近くの選手が**拾う**（2.5 秒で自動で投げる今のキャッチと同じ） |
| B | ドロップターゲットのごほうび（シュートポスト）がなくなる | 倒した側の**コースターの射出装置**に球を送り、相手の内野を撃つ（今の射出装置をそのまま使う） |
| C | 球を返す手段が、キャッチと投げるだけになる。CPU はキャッチをしない | CPU にキャッチと投げるを足す（強さごとに、構える早さ・ねらい・ミス） |
| D | コースターにフリッパーの球しか乗らない | 持ち主の選手が投げた球が乗るように変える |

## 3. 新しいコート（案。5 と 6 の決定で、長さと内野は変えないことにした）

- 長さ：ゴール側の壁を中へ寄せる（Z 13.5 → 約 10）。内野は Z 1.0〜壁の手前まで。

- FE で消すもの：モード選択の「P1 のフリッパー」「P2 のフリッパー」、あそびかたのフリッパーの説明（画像と文）。

## 11. 背面のバンパーのラリーを直した（2026-11-27）
- ユーザーが遊んだ結果：背面の加速レーン（入口、分かれ方、出口、白い球、ふた、サーブ、射出装置の位置）は問題なし。ただ、**背面のバンパーどうしでラリーが始まる**。
- わけ：バンパーは「はじく向きを必ずコートの内側（X = 0 の方）へ向ける」決まり（もとは壁ぎわのバンパー用）。入口の左右のバンパー（X ±2.4）は向かい合っているので、はじいた球が反対側のバンパーへまっすぐ飛び、またはじき返される。
- 直し方：`DBBumper` に `useInwardRule`（ON = 今までの壁ぎわ用）と `biasDirection`／`minBias` を足した。背面のバンパーは OFF にして、はじく向きに必ず中央の線の方を 0.45 以上入れる（真横から当たっても、約 27° 上へはじく）。左右の向きはそのまま残る。
  - 目安：X +2.4 のバンパーから真横へはじかれた球は、反対側のバンパー（X -2.4）に着くころには Z で約 1.7 上を通る（台の傾きも入れて計算）。
- `DBTableBuilder` の `BuildBackBumpers` で、背面のバンパーに入れる。中央の線のバンパー（今は外している）は、今までの決まりのまま。
- コンパイル：Editor の外で、エラー 0 件。Unity で台を作り直す（Build Dodgeball Table → シーンを保存）。

## 12. 球を拾うのをなくした（2026-11-27）
- ユーザーの判断：背面の加速レーンとバンパーで、球がフィールドで止まらなくなったので、**拾うのはなくす**。

  - 相手の球：強さに合わせた割合（EASY 35%／NORMAL 60%／HARD 85%）で、よけずにキャッチしにいく。誰の球でもない（白い）球は、いつもキャッチしにいく。

  - キャッチした球は、少し持ってから（EASY 1.0／NORMAL 0.6／HARD 0.35 秒）、相手のいちばん近い選手をねらって投げる。
