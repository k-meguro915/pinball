## 7. フォルダを組み直すときに気をつけること

1. **Editor のツールがパスを直に書いている**。フォルダを動かすと、台やアセットを作り直すときに古い場所へ作ってしまう。
   - `Pinball/Scripts/Editor/PinballTableBuilder.cs`：`"Assets/Pinball/Generated"`、`"Assets/Pinball"`
   - `PinballDodgeball/Editor/DBTableBuilder.cs`：`"Assets/PinballDodgeball"`
   - `PinballUI/Scripts/Editor/PinballHudMenu.cs`：`"Assets/PinballUI/Data"`、`"Assets/PinballUI"`
   - `PinballUI/Scripts/Editor/PinballFontSetup.cs`：`"Assets/PinballUI/Fonts"`
   - `ControlsGuide/Scripts/Editor/ControlsGuideMenu.cs`：`"Assets/ControlsGuide/Data"`、`"Assets/ControlsGuide"`
   → どれも本編のファイルなので、直すかどうかは先に相談する。
2. **Resources の名前を変えない**：`ControlsGuide/Resources`、`TextMesh Pro/Resources`
3. **動かすときは Unity の中で**：Project ウィンドウで動かせば `.meta`（GUID）が残り、シーンや設定の参照は切れない。エクスプローラーで動かすときは `.meta` も必ず一緒に動かす。
4. **namespace とフォルダは関係していない**：asmdef が無いので、フォルダを動かしてもコンパイルには影響しない。asmdef を入れるなら、3 章の依存の向き（PinballUI → Pinball）に合わせる。
5. **Build Settings**：今はドッジボールのシーンが入っていない。1 本にまとめるときに、FE のシーンと両方のルールのシーンを登録する。

## 付録：調べ方

- 全部の `.meta` から GUID とパスの対応表を作り、シーンの YAML から `guid:` をたどって依存を集めた（マテリアル → シェーダーなども含む）。
- スクリプトは各ファイルの `<summary>` と、`AddComponent`、`Resources.Load`、`Shader.Find`、`"Assets/..."` を grep した。
- コードの中で型名から作られるもの、リフレクションで読まれるものは、GUID をたどっても出てこないので grep で補った。
